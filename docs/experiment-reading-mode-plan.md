# Experiment Vault, Reading Modes, and Identity Chronology

## Evidence standard

The experiment vault will label entries as **prototype**, **study**, or **shader** and will describe them as compact demonstrations rather than finished client outcomes. No performance, adoption, or commercial result will be claimed without public evidence. The identity timeline will use only already verified public repositories and the existing public portfolio record.

## Reading modes

| Mode | Primary visitor | Content emphasis |
|---|---|---|
| Recruiter | Hiring managers and collaborators | Role, scope, stack, delivery evidence, and a short outcome summary. |
| Visual | Designers and experience-focused visitors | Lead image, interaction intent, motion vocabulary, and visual composition. |
| Technical | Developers and technical reviewers | Architecture, runtime, repository evidence, and implementation notes. |

The switch will be a compact segmented control with persistent in-page state only. Each mode will preserve the same URL and project identity, while collapsing non-essential content rather than duplicating the entire case study.

## Collision safeguards

Every chapter index will remain in normal layout flow. Generated labels will not occupy absolute coordinates inside text blocks. Rail labels will use reserved columns and `min-width: 0`; bilingual strings will wrap naturally with `overflow-wrap: anywhere`. Mobile layouts will stack index, heading, and evidence blocks in separate rows with no negative offsets.
